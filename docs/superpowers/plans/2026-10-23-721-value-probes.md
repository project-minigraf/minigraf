# Value probes (#721) — Plan

Issue: #721. One PR to `v3`, merge commit, no closing keyword (the issue is closed by hand on
merge). #551 PR 3 waits for it, so its envelope records the fixed recursion numbers.

## Problem

A join whose inner pattern shares only its value with the rows so far (`[?x :manager ?y]` with
`?y` bound) is a `HashJoin` that holds or streams every fact of the attribute. In a rule's delta
run it does so every round: #700 orders the ancestors shape's delta run that way, and
`recursive_ancestors` went from 2 ms to 1.8 s at 1M facts and 35 s at 10M. The engine probes
by entity only; a value probe was left out because the pending store has no value index
(#545 plan, decision 3).

## Decisions

1. **`JoinKind::ProbeValue(k)`**: when the inner pattern's entity is not bound, its attribute is a
   constant, its value is key `k`, and it reads no derived relation, the join probes per outer
   row instead of hashing. An entity probe still wins when both apply. A pattern that reads a
   relation keeps the `HashJoin` (relations are indexed by entity only). The operator is still
   an `IndexNestedLoopJoin`.
2. **Committed side: AVET ranges of the values that join-equal the outer cell** (the join rules,
   spec §5.4 of #473):
   - a keyword ident `i`: `Keyword(i)` and `Ref(e)` of the entity `i` names, where each is a
     DICT id;
   - an entity `e`: `Ref(e)` and `Keyword(i)` for the keyword naming `e`, found through a map
     from named entity to keyword ident, built once per scan from the attribute's keyword range
     (at most what today's `HashJoin` reads, and only for entity cells);
   - a float `f`: `Float(f)`, and `Float(-f)` when `f` is zero; NaN reads nothing;
   - any other scalar: its committed key value, if the generation can hold it.
   The ranges are a superset of the join: the join still checks every key, the probed one too, so
   answers are the `HashJoin`'s.
3. **Pending side: a map from join key to the attribute's live pending facts**, built on the first
   probe from one `pending_live` read of the attribute and charged to the meter. The shadow set
   (committed triples a pending record decides) is built once per scan too, not per probe.
4. **No answer changes.** The frozen answers (`tests/answers/`), the plan-independence matrix and
   the model-based tests must pass unchanged.

## Steps

Each step builds and passes clippy on all targets and features and leaves the suite passing,
plain and with `--features test-hooks`; tests run on the bench machine.

1. **Plan.** This file.
2. **Planner:** `JoinKind::ProbeValue`, chosen per decision 1; a pattern with a derived relation
   is downgraded to a `HashJoin` before the build-side choice. Test: the ancestors shape's delta
   run (`(boss :leaf ?b)` after the magic-set rewrite) has no `HashJoin` over a stored pattern,
   and the #694 fan-out shape keeps no keyless join.
3. **Scan and join:** `Scan::probe_value` (decisions 2, 3), the join's per-row probe and key
   check. Tests: a value join reads only the probed keys (operator counters) on a checkpointed
   file, with pending facts, and after a pending retraction of a committed fact; keyword ↔ ref in
   both directions, an entity cell against keyword values, `0.0`/`-0.0`, NaN, a long string
   committed and pending, `:as-of` and `:valid-at`; the same answers as with probes off.
4. **Measure and document:** Criterion `recursion` benches and the #394 envelope at 100K/1M/10M
   against `v3`, A/B on the bench machine; `CHANGELOG.md` (`Fixed`, #721), `CLAUDE.md` (engine
   notes), `docs/TEST_COVERAGE.md`, test counts; release binary size (gate 1,200 KiB).
