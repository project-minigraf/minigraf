# Soak test at scale — Plan

Spec: `docs/superpowers/specs/2026-10-10-soak-test-design.md` (#392).

## v3 PR (`test/392-soak` → `v3`)

1. `tests/soak_test.rs`
   - `Config` (from env for `soak`, fixed for `soak_short`), `Every` schedule by
     time or by step count so the short run is deterministic in a debug build.
   - `Reference`: `content(n)` slots, `flipped` Vec + index map, hot history as
     packed `u64`s, `tx`.
   - `Driver`: op choice by phase weights, checkpoint and reopen schedule,
     churn rate cap with checked reads in between.
   - Checks: EAVT, AVET, AEVT shard, hot `:as-of`, tx counter; end: full-scan
     count and `verify()`.
   - `Metrics`: latency samples per path, checkpoint times, open times, RSS
     from `/proc/self/status`; JSON lines via `serde_json`.
   - Memory bound after the growth phase (spec §8).
2. Run `soak_short` in debug; run `soak` locally with a reduced target and a
   few minutes; then a full 10M run under `--profile bench`.
3. `.github/workflows/soak.yml` (spec §9).
4. Docs: `docs/TEST_COVERAGE.md`, `CLAUDE.md` test count, `ROADMAP.md` if it
   lists #392, `CHANGELOG.md` Unreleased.
5. PR to `v3` without a closing keyword for the tracker; `Closes #392` only
   in the main PR description if the user wants it closed on merge.
