## PR 0: #734

Worktree `.worktrees/180-udf-ffi`, branch `fix/734-tx-guards` from `origin/v3` (this plan is its first commit).

1. **Tests** in a new `tests/write_tx_guard_test.rs` (`#![cfg(not(target_arch = "wasm32"))]`). There is one test per method: `checkpoint`, `verify`, `rebuild_indexes`, `prepare`, `PreparedQuery::execute`, `PreparedQuery::query`. Each runs on a file database, with a `WriteTransaction` open on the test's thread, and expects `ErrorCode::Int001`. Each scenario runs in a spawned thread, and the test waits on a channel with `recv_timeout(Duration::from_secs(30))`, so a deadlock fails the test instead of hanging CI. Today `checkpoint`/`verify`/`rebuild_indexes` time out, and the prepared ones return `Ok`. A further test checks that the transaction still commits after each refusal.
2. **Code**: an `is_write_tx_active()` → `bail_coded!(ErrorCode::Int001)` check at the top of each method in step 1's list. It goes before `reject_if_read_only`, matching `execute_inner`. `is_write_tx_active` becomes `pub(crate)` for `prepared.rs`.
3. **Docs**: `docs/ERROR_REFERENCE.md` INT-001 lists every method that raises it. `CHANGELOG.md` v3.0.0 gets a `Fixed` entry. `docs/TEST_COVERAGE.md` and the `CLAUDE.md` test counts are updated. The #421 entry gets "Fix: merged on `v3` in PR #…".
4. **Backport to `main`**: worktree `.worktrees/734-tx-guards-main` from `origin/main`. On v2.x the guard goes on `checkpoint` and the prepared methods (`verify`/`rebuild_indexes` do not exist there), with step 1's tests for those. CHANGELOG `Unreleased` → `Fixed`. #734 stays open until the v2.x patch with it is published (support policy: v2.0.x gets bug fixes until v3.0.0).

## PR 1: fallible UDFs and the registry snapshot

Worktree `.worktrees/180-udf-ffi` (reused), branch `feat/180-fallible-udfs` from `origin/v3` after PR 0.

5. **`UdfError` and `QRY-014`.** `UdfError` (spec §3) goes in `src/query/datalog/functions.rs` and is re-exported from `lib.rs` next to `MinigrafError`. `ErrorCode::Qry014` gets its message ``user function `{}` failed: {}`` and category `Query`, in the registry list and the code↔doc tests (`error_codes_foundation_test.rs`), plus `docs/ERROR_REFERENCE.md`. First check that #306's branch or any open v3 PR has not claimed `QRY-014` (`git grep QRY-014 origin/v3 $(git branch -r --list 'origin/feat/*')`). Test: the code's string, category, and doc entry.
6. **Fallible descriptors.** `PredicateDesc::f: Arc<dyn Fn(&Value) -> Result<bool, UdfError> + Send + Sync>`, and `UdfOps::init`, `UdfStepFn`, `UdfFinaliseFn` likewise return `Result`. `register_predicate_inner`/`register_aggregate_inner` take the fallible closures. `register_*` wrap the user's closure in `Ok`, and the new `try_register_*` (spec §3) pass it through. The built-in sentinels (`|_| false`) become `|_| Ok(false)`. Test (`udf_test.rs`): every existing UDF test also runs through `try_register_*` with never-failing closures and gets the same rows (one parametrised helper).
7. **Predicate failures.** `pub(crate) enum EvalError { NoValue, Udf(anyhow::Error) }`. `eval_expr` returns `Result<Value, EvalError>`: today's `Err(())` becomes `NoValue`, and a failing predicate becomes `Udf(err_coded!(Qry014, name, e.message()))`. The `?` chains carry both. `filter::eval` maps `NoValue` → `Ok(None)` and `Udf(e)` → `Err(e)`. The unit tests on `eval_expr` (`executor.rs:1994…`) compare against `Err(EvalError::NoValue)` (`EvalError: PartialEq` by variant, under `cfg(test)`). Tests (`udf_test.rs`): a `try_` predicate that fails on one value, with an `AtomicUsize` call counter, in `:where`, a rule body, a `not` body and an `or` branch, through `execute`, `query` + `next_batch` (rows before the failure come first, then the error, then `None`), and `PreparedQuery::execute`. Each asserts `Qry014`, the name and message in the text, and that the counter stops at the failing call.
8. **Aggregate failures.** `Udf::of` → `Result<Option<Udf>>` (init's error is `QRY-014`), and `Udf::add`/`value` → `Result`. `Agg::add` and `Running::add`/`value` → `Result<…>`, with built-in arms `Ok(…)`. `windows`, `finish_groups`, `engine/aggregate.rs`, `engine/window.rs` propagate with `?`. A failure in `step` stops the query at that value. Tests: `try_` aggregates failing in `init`, `step` and `finalise`, each as a `:find` aggregate and as an `:over` window. Each asserts `Qry014` and that no call follows the failing one.
9. **Registry snapshot.** `pub(crate) struct Functions(RwLock<Arc<FunctionRegistry>>)`, with `snapshot() -> Result<Arc<FunctionRegistry>>` (read lock for the clone only; poisoned → `QRY-008`) and `register(|reg| …)` (write lock, `(*arc).clone()`, mutate, swap; poisoned → `API-008`). `FunctionRegistry: Clone`. Every holder in "Call sites" takes `Arc<Functions>`. The engine's `Stream` and `open`/`open_rules` take the `Arc<FunctionRegistry>` snapshot instead. The executor takes it once in `open_query`/`open_rule_query`, before the `QRY-007`/`QRY-010`/`QRY-011` checks, and uses that one snapshot for the checks and the stream. `pull` and `open_rules` no longer lock. Tests: a predicate that calls `db.register_predicate` mid-query returns, where today it deadlocks (step 1's timeout harness). A cursor opened before a registration does not see the new function (`QRY-007` stays the open-time answer; a later query sees it).
10. **Re-entry tests**, one per row of spec §5's table, for both columns, on a file database with pending and committed facts. From inside a predicate: query `execute`, `query` drained, `prepare` + `execute`, `fact_log`, `transact`, `retract`, `rule`, `begin_write` + commit, `checkpoint`, `verify`, `rebuild_indexes`, `register_*`, and a nested query that calls a second UDF. Plain-read column: each runs. A write is not seen by the outer query, and the outer query's rows equal those of the same query without the callback's side effect. Write-transaction column: `INT-001` for each row that says so, and registration runs. All of them go through the timeout harness.
11. **Lock audit.** Check that no `Mutex`/`RwLock` guard is alive at any UDF call: grep `\.read()\|\.write()\|\.lock()` under `src/query`, `src/graph/storage.rs`, `src/storage/cache.rs`, `src/storage/reader.rs`, and trace each guard's scope against `filter::eval` and the aggregate/window call sites. Record the result (file:line per guard, and why it is not held) in the PR body. A guard found alive gets a fix and a re-entry test.
12. **Docs.** `db.rs` doc comments on the four registration methods: the failure rule, the snapshot rule, and re-entry (spec §5 table, as prose). `CHANGELOG.md` v3.0.0 `Added`: the `try_` methods and `UdfError`, `QRY-014`, re-entrant UDFs, and the snapshot rule. `CLAUDE.md` module notes (`functions.rs`: `Functions` snapshot, `UdfError`) and test counts. `docs/TEST_COVERAGE.md`. Docs site: worktree `../minigraf-docs/.worktrees/180`, the UDF section of `content/datalog-reference.md` (and `content/architecture.md` if it names the registry) inside `<!-- @since v3.0.0 -->`. That PR merges after PR 1.
13. **Acceptance.** On the bench: full suite plain and `--features test-hooks`, the coverage gates (`coverage-thresholds.toml`; a new file's floors added if needed), and the release binary size against v3 (spec: a few KiB). Codex review. CI green, then ask to merge.
