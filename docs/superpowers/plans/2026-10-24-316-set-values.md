## Decisions not fixed by the spec

1. **Long-value reads become byte reads.** `DictReader::long_value` returns `String` and fails
   `STG-036` on non-UTF-8 bytes (`dict.rs:203`), and `find_long_value` compares candidates as strings
   (`dict.rs:219`). A set record is not UTF-8, so a string whose `hash64` collides with a set's would
   fail instead of missing. Add `DictReader::long_bytes(vref) -> Result<Vec<u8>>` (the cache keyed by
   `ValueRef` holds bytes), make `long_value` a UTF-8 view of it, and make the dedup lookup
   `find_long_bytes(&[u8])`, comparing bytes. `KeySource` gains `long_bytes` and `long_bytes_ref`;
   `long_value_ref(s)` becomes `long_bytes_ref(s.as_bytes())`.
2. **The `Encoder` stages long values as bytes.** `new_values: Vec<String>` / `new_long:
   HashMap<String, usize>` (`dict.rs:376-394`) become `Vec<LongValue>` keyed by bytes, where
   `LongValue { bytes, kind: Str | Set { prefix } }`, so `finish` builds `keys::long_str` or
   `keys::long_set` from the returned ref. One dedup table serves both kinds (spec §4.2).
3. **A set's v8 element encoding needs ids first.** `Encoder::value` for `Value::Set` assigns each
   keyword and ref element's id with `self.iid` / `self.eid` (as the scalar arms do), builds each
   element's `KeyValue` (`Str` for every string, whatever its length), encodes and sorts them
   (`keys::set_elements(&[KeyValue]) -> Vec<u8>`), then inlines (`KeyValue::Set`) or stages a long
   value. `keys::set_bytes_bound(&ValueSet) -> usize` (spec §3, no ids) lives in `keys.rs` next to it,
   so the WAL check and the encoder share one definition.
4. **Committed sets are decoded at scan.** `Cell::of_key` stays infallible and has no DICT access, so
   the committed scan (`scan.rs:462`) calls a new `Cell::of_key_with(&kf.v, ctx.keys)` that is
   `of_key` for every other value and, for `Set`/`LongSet`, decodes elements through
   `KeySource::ident_of`/`uuid_of` (and `long_bytes`) into `Scalar::Set(Arc<ValueSet>)` (spec §8).
   `Cell::of_value` maps `Value::Set` straight to it.
5. **Golden corpus.** The spec's §12 asks for a golden-file entry with sets. The corpus is v7 files
   (`tests/golden/`, never regenerated), and v7 has no sets, so there is nothing to add. The
   reopen, checkpoint and WAL-replay tests of step 6 cover persistence instead.
6. **`Value` match sites outside the crate's API.** `Value` becomes `#[non_exhaustive]`, which only
   affects other crates. Inside the crate every exhaustive match gets a real `Set` arm, never `_`, so
   the compiler finds each one: `types.rs`, `aggregate.rs`, `functions.rs`, `executor.rs`, `repl.rs`,
   `engine/project.rs`, `engine/cell.rs`, `engine/scan.rs`, `engine/plan.rs`, `prepared.rs`,
   `parser.rs`, `matcher.rs`, `db.rs`, `browser/mod.rs`, `storage/{index,keys,dict,verify}.rs`.
   Examples and tests in this repo that match exhaustively also get an arm.

## PR 1 — set values

### Step 1. `ValueSet` and `Value::Set`

- `graph/types.rs`: `ValueSet` (spec §3) with `new`, `iter`, `len`, `is_empty`, `contains`,
  `IntoIterator for &ValueSet`; `new` uses `get` + `replace` for the `value_order`-least float
  (spec §3, "Inserting an equal float"). `Value::Set(ValueSet)` after `Null`; `#[non_exhaustive]`
  on `Value`. Discriminant 7 in `Ord`'s cross-variant arm (`types.rs:160`); `Set` arms in `Ord`
  (lexicographic over `iter()`), `Hash` (len, then elements), the docs table above `Value`, and
  `as_*` helpers (none returns a set; add `as_set`).
- Serde: `impl Serialize for ValueSet` (seq) and a hand-written `Deserialize` that collects
  `Vec<Value>` and calls `new`, mapping `API-021` to a serde error.
- `error.rs`: `Api021` ("a set cannot hold a set"), four sites as `Api020`; `ERROR_REFERENCE.md`.
- `lib.rs`: re-export `ValueSet` beside `Value`.
- Tests (`types.rs` unit): dedup; `#{0.0 -0.0}` and `#{-0.0 0.0}` hold `-0.0` (check
  `is_sign_negative`); several NaNs give one; nested set `API-021`; proptest over random scalar sets:
  `a == b ⇒ hash(a) == hash(b)`, `cmp` antisymmetric and transitive, `new` independent of insertion
  order; postcard round trip; postcard of a non-canonical sequence restores the order; postcard of a
  nested set fails; postcard of each pre-existing variant unchanged (bytes fixed in the test).

### Step 14. Evaluation

`executor.rs` `eval_binop`, the arm after `Matches` (the engine's `Filter`/`Bind` call
`eval_expr`, so both forms follow):

| op | `(l, r)` accepted | result |
|---|---|---|
| `In` / `NotIn` | `l` not a set, `r` a set | `r.contains(&l)` / its negation |
| `AnyIn` / `NoneIn` | both sets | some element of `l` in `r` / its negation |
| `AllIn` | both sets | every element of `l` in `r` |

Every other shape is `Err(())`. `ValueSet::contains` is the `BTreeSet` lookup under `Value`'s `Ord`,
which is the spec's set equality (§2), so NaN, `-0.0`/`0.0` and keyword ≠ ref follow with no special
case. Iterate the smaller set for `AnyIn`/`NoneIn`; `AllIn` returns false at once when `l` is larger.
Unit tests in `executor.rs` next to `test_eval_contains_true`: each op true and false, every
empty-set case of spec §6, each wrong shape.
