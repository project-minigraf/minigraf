## Design decisions not fixed by the spec

1. **`Meter` and `Held`** live in a new `src/query/engine/meter.rs`.
   `Meter { limit: usize, used: AtomicUsize, peak: AtomicUsize }`, shared as `Arc<Meter>`.
   Each holder owns a `Held { meter: Arc<Meter>, op: &'static str, bytes: usize }`:
   `charge(n) -> Result<()>` (spec §3.1 steps 1–2, saturating arithmetic, `peak` by
   `fetch_max`), `uncharge(n)` (an entry let go), `release()` (subtract `bytes`, set it to 0),
   and `Drop` calls `release`. So an operator's `Drop` needs no code of its own, and `rewind`
   and `close` call `release` where they clear their tables. `peak` is for tests and PR 2's
   figures; nothing public reads it.
2. **The allocator form.** `TryReserveError` does not expose the size it asked for on stable
   Rust, so the message's `{n}` is the estimate `entry × max(capacity, 1)`: the bytes the
   container's doubling would have added. `Held::reserve(charged, refused, r)` turns
   `r: Result<(), TryReserveError>` into `QRY-012` and uncharges `charged` on failure.
   Under `cfg(test)`, a thread-local `FAIL_RESERVE: Cell<Option<&'static str>>` makes the
   next `reserve` of that `op` fail (spec §6.2's test hook).
3. **How the meter reaches holders.** `build(source, steps, &Arc<Meter>)` passes it to every
   operator constructor, and so to `not` bodies, `or` branches and correlated sub-plans,
   which `build` builds. `IdSpace::new(keys, meter)`, `Relations::new(iids, meter)`, and
   `recursive::heads` / `know_stored` take a local `Held` that drops on return. `Stream`
   keeps the `Arc` (and `Stream::meter()` under `cfg(test)`). `engine::open` takes the
   limit; `recursive::Limits` gains `query_memory: usize` for `open_rules`.
4. **Executor plumbing.** `DatalogExecutor` is not public API (`mod query` is private), so
   `set_limits` becomes `set_limits(max_derived_facts, query_memory_limit)` at its four
   `db.rs` call sites, with a `query_memory_limit` field defaulting to `usize::MAX`, copied
   by `oracle()`.
5. **`Stream::close`** closes the root (releasing every operator), then empties the
   `IdSpace` (provisional and DICT maps, `IdSpace::release`) and drops the `Relations`, so
   the meter is 0 after a drain, an early close, an error, and a dropped cursor.
6. **Holders added to the spec's table** (§3.2 says every holder of more than one batch
   counts; these were missed). Listed here as deviations from the approved spec:
   - `Relations::know`: each stored fact's identity key and its hash entry. `know_stored`
     inserts one per stored fact of an evaluated attribute, which can be every fact.
   - `sum-distinct`: each new member of `Agg::SumDistinct`'s set, as `count-distinct`'s
     (`size_of::<Value>()`, the string's length, `HASH_ENTRY_OVERHEAD`). `Agg` gains
     `pub(crate) fn would_add(&self, v: &Value) -> bool` so the charge comes before the
     insert.
   - Not counted: a UDF accumulator's state (opaque), `min`/`max`'s one held value per
     group (inside the fixed `Group` size), and the value columns `aggregate::windows`
     returns (the executor's code, freed before `finish` returns). Only the cells `finish`
     appends to each row are charged.
7. **Release of buffered output.** `Union`'s `At.rows`, and `Aggregate`'s and `Window`'s
   finished rows, are uncharged one row at a time as they go into a batch, so a stream that
   has returned most of an answer holds little.
8. **`Counters`** gains `bytes_held: u64`, set from the operator's `Held` when `counters()`
   pushes it. A holder with two `Held`s (`IdSpace`) is not an operator and has no counters.
9. **`QRY-012`'s registry text** is `query memory limit exceeded: {}`, the two forms of
   spec §4 passed as the tail.
10. **The oracle** (`oracle::check`) accepts `(Err(e), _)` when `e` downcasts to a
    `CodedError` with code `QRY-012`, whatever the executor answered.
11. **Keyless build side.** `optimizer::product_cost(&[WhereClause]) -> u64`, beside
    `branch_cost`: the saturating product of `pattern_cost` over the patterns, 0 for none.
    In `plan.rs`, a `JoinKind::Hash` whose `join.keys` is empty uses it for the outer side
    (spec §6.1); the reorder switch still forces the inner side.

## PR 1 — meter, accounting, `QRY-012`, option

1. **`meter.rs`** (decisions 1, 2): `Meter`, `Held`, `HASH_ENTRY_OVERHEAD = 16`,
   `cell_bytes`, `key_bytes`, `row_bytes`, the test hook. Unit tests: a charge over the
   limit is `QRY-012` naming the op and counts nothing; `release` and `Drop` return the
   bytes; `peak`; `reserve` failure uncharges and gives the allocator form; `usize::MAX`
   never fails.
2. **`ErrorCode::Qry012`** in `src/error.rs` (enum in place of the reserved comment,
   `REGISTRY`, the exhaustive category match, `ALL`); `docs/ERROR_REFERENCE.md` row and
   section (cause, resolution, example), and the "(QRY-012 is reserved.)" note removed from
   `QRY-013`.
3. **Option and plumbing** (decisions 3, 4): `OpenOptions::query_memory_limit` field
   (doc: what is counted, engine-only gap until #551, 0 fails any stateful query), builder,
   `Default` `usize::MAX`; `set_limits`; `engine::open`/`open_rules`/`Limits`; `build` and
   the operator constructors; `IdSpace::new`; `Relations::new`; `Stream::for_test` with an
   unlimited meter.
4. **Join, AntiJoin, Union, Distinct** (spec §3.2 rows 1–5): charge before each insert,
   `try_reserve(1)` on each container grown (`by_key`, `buckets`, a bucket; `set.keys`; the
   branch table, its row vectors, `At.rows`; `seen`), release on `rewind`/`close`.
   `AntiJoin`'s and `Union`'s hashed tables survive a rewind today, and so does their charge.
5. **Aggregate and Window** (rows 6–7, decisions 6, 7): groups, `count-distinct` and
   `sum-distinct` members, finished rows; held cells and values.
6. **Rule queries** (rows 8–9): `Relations::add` and `know` return `Result` and charge;
   callers in `open_rules` and `recursive::evaluate` propagate. `know_stored`'s `stored` and
   `heads`' `out`/`seen` charge into a local `Held`.
7. **`IdSpace`** (rows 10–11): one `Held` for provisional ids, one for the DICT cache;
   `end_pull` releases the DICT one. `Stream::close` (decision 5).
8. **Oracle** (decision 10) and **keyless build side** (decision 11).
9. **Tests.** In `src/query/engine/tests.rs`: each holder charges on insert and releases on
   `rewind` and `close` (the meter's `used` read between pulls); `used` is 0 after a drain,
   an early close and an error; `QRY-012` names each operator (`HashJoin`, `AntiJoin`,
   `Union`, `Distinct`, `Aggregate`, `Window`, `Relations`, `IdSpace`) at a limit just
   below its charge; the allocator form per op through the hook; the keyless build side
   (#575 shape builds inner from the second join on; `[?e :name "x"] [?p ?q ?r]` builds
   outer; a tie builds inner; reorder off builds inner). New `tests/memory_limit_test.rs`
   (in-memory, public API only): default `usize::MAX`, builder; `QRY-012` through
   `execute`, `query`, a prepared query and a rule query; a cursor that returned rows gets
   the error on the next call and the database then answers another query; a write
   transaction's query is not limited (the documented executor gap).
10. **Docs and checks.** `CHANGELOG.md` (Added: the option and `QRY-012`; Changed: keyless
    joins build on the side with the smaller product estimate), `CLAUDE.md` (module list:
    `meter.rs`; counts), `docs/TEST_COVERAGE.md`. Binary size against the 1260 KiB v3 gate.
    Envelope 100K and 1M on the bench machine (idle first), before and after, for the scan,
    join and aggregate shapes: the accounting adds an atomic add per insert and must not
    move them beyond noise. Codex review (`< /dev/null`), CI green, ask before merge (merge
    commit, admin bypass). Docs-site PR `v3/549-memory-limit`.

## PR 2 — acceptance and measurement

11. `tests/memory_limit_acceptance_test.rs` (`#![cfg(target_os = "linux")]`, both tests
    `#[ignore]`d, peak RSS by resetting `VmHWM` as `recursive_acceptance_test.rs` does):
    1M groups (no limit: 1M rows; limit 32 MiB: `QRY-012` naming `Aggregate`) and #575 at
    k = 13 (drain 3^13 rows through `Minigraf::query`, peak RSS < 64 MiB; limit 64 B:
    `QRY-012` naming `HashJoin`). Deviation from spec §6.2: an integration test cannot read
    the meter's counters, so test 1's limit is fixed below the floor every group costs
    (1M × at least 40 bytes, a key and its hash entry) instead of read from a first run.
12. `smoke.yml` job: `cargo test --profile bench --test memory_limit_acceptance_test --
    --ignored` without `test-oracle`.
13. Measured figures: an ignored engine test prints the meter's `peak` for both shapes;
    the PR and `docs/` give peak against RSS (spec §3.2's factor of two). Codex review, CI,
    ask before merge. Close #549 by hand.
