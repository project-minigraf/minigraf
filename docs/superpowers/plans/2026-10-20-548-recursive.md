## Design decisions not fixed by the spec

1. **How a derived fact is marked.** `Fact::new(…, 0)` already gives tx-count 0, tx-id 0,
   valid-from 0 and valid-to forever. `RecursiveEvaluator` loads its delta with
   `FactStorage::load_facts` and `StratifiedEvaluator`'s mixed pass with `load_fact`,
   instead of `FactStorage::transact`, so the mark survives; the positive pass already
   copied facts with `load_fact`. `FactStorage::transact` has no other non-test caller and
   becomes `#[cfg(test)]` (writes go through `transact_batch`).
2. **Where `nil` is decided.** `PatternMatcher::metadata` returns `Value::Null` for a
   tx-count-0 fact, for every per-fact pseudo-attribute. No stored fact has tx-count 0:
   the counter starts at 1, the v1 migration on v2.x numbered from 1, and `LogWriter`
   rejects 0 (`API-015`). Magic seeds also have tx-count 0 and are query-local; they bind
   `nil` too, which matches spec §3.3 (they are not stored facts of the snapshot).
   `:db/valid-at` is not per fact and is unchanged.
3. **`QRY-013`'s text** names the predicate and the kind of the value:
   `rule head entity is not an entity: rule '{}' gives a {} where a ref or a keyword is
   needed`, the kind from `aggregate::type_name` (made `pub(crate)`), `symbol` for a bare
   symbol in the head. `QRY-012` stays reserved for #549 (a comment in `ErrorCode`).
4. **The mixed pass propagates `instantiate_head`'s error** (`?`), so an unbound head
   variable is `INT-022` there too (spec §3.4), with the same text as the positive path.
5. **The function registry in rule-body `or` branches** is a read guard on
   `StratifiedEvaluator::functions`, taken where `FunctionRegistry::with_builtins()` was.

## PR 2 — `Recursive` and rule queries on the engine

8. **Relation store** (`src/query/engine/relation.rs`): per evaluated predicate an
   append-only `Vec` of `[Cell; 2]` rows, an identity `HashSet` (spec §3.2: floats by
   bits with `-0.0` ≠ `0.0` and one NaN; a keyword `Iid` distinct from the `Eid` it names;
   long strings by content), an entity-key index to row positions, and round boundaries
   (`start_k`, `end_k`). Seeding: each stratum predicate's identity set from one scan of
   its stored facts; magic seeds appended as rows before round 1. Unit tests for identity
   and ranges.
9. **Derived scan source** (`plan.rs` `ScanSpec`, `scan.rs`): `derived: Option<Derived>`
   with the predicates read (one for `:p`, every evaluated one for a variable or `_`
   attribute, the attribute cell the ident of `:p`) and a `Range` (`Full`, `Old`,
   `Delta`). `Full`/`Old` read committed, pending, then derived rows; `Delta` derived
   rows only. Derived rows fill metadata columns with `nil`; entity probes use the
   relation's index. Constants and bound values filter as on the other sources.
10. **Rule bodies as plans**: a `Builder` entry that plans a rule body (invocations as
    `rule_invocation_to_pattern` patterns) and ends in a head projection of two cells
    (entity checked as spec §5.3: `Eid`, or `Iid` via `IdSpace::keyword_eid`, else
    `QRY-013`; one-argument heads project `true`). `None` (executor) when a body cannot
    be planned.
11. **`Recursive`** (`src/query/engine/recursive.rs`): strata from `stratify()` over the
    evaluated predicates (`all_preds` as `StratifiedEvaluator::evaluate`); round 1 every
    rule `Full`; round `k > 1` one variant per same-stratum top-level invocation
    (`Delta` / `Old` before / `Full` after); naive rules (spec §5.3's list, found on the
    parsed body) every round, all `Full`; heads checked against the identity set,
    appended at the round's end, each counted against `max_derived_facts`; `INT-020`
    after `max_iterations` rounds (the empty round counts).
12. **Query body**: planned as any engine query after `Recursive`, every scan with the
    derived source `Full`.
13. **Routing** (`DatalogExecutor::open_query`): a rule query goes to the engine when its
    body and every evaluated rule body plan, it has no `:as-of` timestamp and no slot left,
    and it is not in a write transaction (`facts_override`); else the executor. The oracle
    compares both (bags, or both errors).
14. **Tests**: `tests/recursive_engine_test.rs` (spec §7's list), every query also through
    the oracle; existing rule suites (`recursive_rules_test`, `negation_test`,
    `disjunction_test`, `magic_sets_test`, model and property tests) now reach the engine.
15. **Binary size** against the 1,230 KiB gate (v3 ~1,211 KiB); if over, the PR says by
    how much and why before the gate moves. `CHANGELOG.md` Internal entry, counts, envelope
    smoke at 100K.

## PR 3 — acceptance and measurement

16. Acceptance test: a layered graph (63 layers of 50 nodes, complete bipartite edges
    between neighbours, ≈ 5M `reach` facts in 63 rounds) completes with peak RSS
    proportional to the derived relation; `max_derived_facts` stops a runaway rule with
    `INT-020`. Ignored by default (run in the soak/bench job), as other large tests.
17. Envelope `recursive` shape (transitive closure at 100K, 1M, 10M base facts) in
    `examples/perf_envelope.rs`.
18. Bench machine A/B (engine against `origin/v3`, `numactl` one node, idle machine):
    wall time and peak RSS; #379 point queries must not regress.
19. Results in `CHANGELOG.md`; close #548 by hand.
