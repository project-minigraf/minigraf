## Decisions not fixed by the spec

1. **Codes are `API-022`, `API-023`, `API-024`**, even if #316's `API-021` has not landed yet. A gap in the registry is allowed: no test requires numbers to be contiguous, and #316's spec has already reserved `API-021`.
2. **The `INT` variants stay in `ErrorCode`** with `#[allow(dead_code)]` and a "deprecated since v3.0.0" comment, as `Stg003`/`Stg004`/`Api013` do. Their registry entries and `ERROR_REFERENCE.md` sections stay, with "(deprecated)" added to the table row and a sentence added to the deprecated-codes paragraph.
3. **The expression slot also accepts `Entity`** (`resolve_val_slot`), as the spec's §3 says. An `Entity(u)` in an expression is `Value::Ref(u)`.
4. **The browser bind reader lives in a new file, `src/browser/binds.rs`**. It holds `fn read_bindings(&JsValue) -> Result<Vec<(String, BindValue)>, JsValue>` and its helpers. A JS `TypeError` is built with `js_sys::TypeError::new`. `API-017` is `MinigrafError::invalid_argument(..)` rendered by `to_js_error`.
5. **Browser limits.** `BrowserDb.prepare` passes `(DEFAULT_MAX_DERIVED_FACTS, usize::MAX)`, the limits `BrowserDb.query` uses today through `DatalogExecutor::new_with_rules_and_functions`.

### Step 6 — `BrowserDb.prepare`
Write `#[wasm_bindgen_test]` cases in `src/browser/mod.rs` first. They are run in CI by `wasm.yml`; locally, `cargo check`/`clippy --target wasm32-unknown-unknown --features browser` and a `wasm-pack test --headless` run if a browser is available:
- prepare once, then `execute` three times with different plain integers, each giving its rows (#181 acceptance);
- each plain form: `true`, an integer `number`, a fractional `number`, a `bigint`, a string, `null`;
- each typed form: `{type:'integer'|'float'|'string'|'boolean'|'ref'|'keyword'|'null'}`, `{type:'entity'}`, `{type:'txCount'}` and `{type:'timestamp'}` with `bigint` and `number`, and `{type:'anyValidTime'}`;
- `{type:'float', value: 2}` binds a float and `2` binds an integer;
- `query(bindings)` drained, with the same rows as `execute`;
- `undefined` and an unknown object are a `TypeError`; a bad UUID and a negative tx count are rejected with a message starting `[API-017] `; a missing slot is rejected with `[API-022] `; an attribute slot passed to `prepare` with `[API-023] `;
- a prepared query sees a later write (it reads a new snapshot on each `execute`).

Then `src/browser/binds.rs` (decision 4) and, in `mod.rs`: `BrowserDb::prepare(&self, datalog: &str) -> Result<BrowserPreparedQuery, JsValue>` (parse; `API-005`/`006`/`007` for a non-query, as `Minigraf::prepare`; `prepare_query` with decision 5's limits), and `BrowserPreparedQuery { _db: Rc<RefCell<BrowserDbInner>>, query: PreparedQuery }` with `execute(&self, bindings: JsValue) -> Result<String, JsValue>` (`query_result_to_json`) and `query(&self, bindings: JsValue) -> Result<BrowserCursor, JsValue>`.
